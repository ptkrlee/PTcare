# 관리자 기능을 실제 사이트에 적용하기

이번 변경에는 **Supabase SQL 업데이트**와 **최초 관리자 지정**이 필요합니다. GitHub/Vercel 배포만으로 데이터베이스 권한이 생기지 않습니다. 공개 키로는 이 두 설정을 대신 실행할 수 없습니다.

## 1. 최신 SQL 실행

1. GitHub의 `ptkrlee/PTcare` 저장소에서 `main` 브랜치를 엽니다.
2. `supabase` 폴더 → `schema.sql` → **Raw**를 클릭합니다.
3. 코드 전체를 복사합니다. 브라우저에서 Ctrl+A, Ctrl+C를 사용할 수 있습니다.
4. Supabase에서 **PTnote 프로젝트 → SQL Editor → 새 쿼리(+)**를 엽니다.
5. 전체 코드를 붙여넣고 **Run**을 누릅니다. `Success. No rows returned`면 다음으로 진행합니다.

기존 SQL을 실행한 적이 있어도 **최신 파일 전체를 다시 실행**해야 합니다. 이 파일은 기존 대상자·평가를 삭제하지 않습니다. 새 권한 테이블에는 기존 가입자도 기본 한도 1명·3회차로 생성되며 승인 대기로 시작합니다. 파일을 다시 실행해도 이후 변경한 승인·한도는 초기화하지 않습니다.

## 2. 최초 관리자 지정

1. 홈페이지에서 본인 이메일로 가입·인증합니다. 가입 계정이 이미 있다면 새로 만들지 않습니다.
2. GitHub `supabase/bootstrap-admin.sql`을 열고 전체 내용을 새 SQL 쿼리에 복사합니다.
3. `REPLACE_WITH_YOUR_SIGNUP_EMAIL` 한 곳을 **홈페이지 가입 이메일**로 바꿉니다. 비밀번호가 아닙니다.
4. **Run**을 누릅니다. 가입 계정이 없거나 이메일이 틀리면 설정하지 않고 오류를 표시합니다.
5. 홈페이지를 새로고침합니다. 상단 **관리자** 버튼을 누르거나 `https://refittherapy.vercel.app/#/admin`으로 이동합니다.

최초 관리자 지정은 프로젝트 소유자가 SQL Editor에서만 실행합니다. 일반 가입자는 관리자 화면이나 API로 스스로 관리자 권한을 만들 수 없습니다. 일반회원과 미인증 치료사회원은 저장 없이 평가·인쇄를 이용할 수 있습니다. 지정된 관리자 본인 계정도 자동 승인됩니다.

## 3. 치료사 승인과 추가 이용권

1. 관리자 화면에서 가입한 치료사 이메일 옆 **이용권 관리 · 기록 열람**을 누릅니다.
2. **치료사 승인**을 체크합니다. 기본값은 대상자 **1명**, 대상자별 **3회차**입니다.
3. **변경 사유**에 승인 또는 이용권 추가 사유를 적고 저장합니다.
4. 치료사는 승인 대기 화면의 **승인 상태 다시 확인**을 누릅니다.
5. 추가 이용권은 **총 한도**로 설정합니다. 예: 3회 + 추가 2회 → **5회**. 대상자 1명 + 추가 1명 → **2명**.

한도는 치료사별로 적용하며, 회차 한도는 그 치료사의 **각 대상자**에게 동일하게 적용됩니다. 한 회차 안의 BBS·MBI·MoCA 등 여러 평가와 운동 계획·경과기록은 한 회차에 포함됩니다. 저장 버튼을 여러 번 누르거나 미완료 항목을 이어 작성해도 추가 차감하지 않습니다. 별도 쿠폰 코드 발행·자동 결제는 포함하지 않습니다.

기존 기록이 한도보다 많아도 삭제하지 않고 이어서 수정할 수 있습니다. 한도 0은 새 대상자/새 회차 추가를 막습니다. 승인 해제는 서버 저장을 막습니다. 보관된 대상자와 충돌 복구본도 대상자 한도에 포함합니다.

## 4. 기록 열람

선택한 치료사의 대상자별 평가 응답·측정값, 회차별 운동·차팅과 전체 원본을 열람합니다. 임상 내용에는 수정 버튼이 없으며 서버도 다른 치료사의 임상 기록 수정을 거부합니다. 이용권 변경 사유·변경 전후 한도·실행 관리자·시각은 별도 감사 테이블에 남습니다.

관리자에게 보이는 것은 **서버 저장 완료된 기록**입니다. 오프라인 기기 임시 저장이나 아직 동기화하지 않은 내용은 보이지 않습니다.

## 5. 확인 순서

가상 데이터만 사용해 가입 → 승인 대기 → 관리자 승인 → 대상자 1명 생성 → 두 번째 대상자 차단 → 3회차 생성 → 4회차 차단 → 한도 추가 → 새 기록 생성 → 다른 치료사 기록 격리 → 관리자 읽기 전용 열람을 확인합니다. Vercel의 최신 배포가 **Ready**인지도 확인하세요.

## 회원 유형 · 요청함 · 아이폰 알림

신규 가입의 일반/치료사 구분, 저장 없는 평가, 인증·이용권 요청 처리 및 아이폰 홈 화면 푸시는 [모바일 알림 설정 안내](MOBILE-NOTIFICATIONS.md)를 따릅니다. 이번 최신 SQL을 설치하면 기존 회원 유형·승인·한도는 유지하고 요청함과 알림 테이블을 추가합니다. 관리자는 회원 구분을 치료사회원으로 설정한 뒤 인증을 승인하거나, 요청함의 인증 요청을 승인할 수 있습니다.
