# 사례와 검토 피드백을 활용하는 차팅

2026-10-31. 이번 방식은 모델 가중치를 재학습하거나, 입력할 때마다 외부 AI 서비스에 환자 기록을 보내는 기능이 아니다. **검토한 작성 사례 + 현재 회차의 중점 + 같은 대상자의 검토 완료 피드백**을 이용하는 명시적인 개인화 규칙이다.

## 첨부 사례 반영 범위

사용자가 제공한 HWP 운동기록지 5건의 본문을 읽고, 운동 방법·제공한 단서·관찰·현장 조정·반응·다음 계획을 구별하는 작성 구조를 확인했다. 개인정보·사진·날짜·진단·검사 결과·개별 환자의 관찰 문장은 공개 코드에 넣지 않았다. 원본 파일은 애플리케이션의 사례 목록이나 서버에 업로드하지 않았다.

12개 일반 작성 패턴은 안정된 앉기/쿠션 지지, 앉은 체중 이동, 상지·어깨뼈 정렬, 호흡, 시각적으로 확인하는 하지 움직임, 브리지와 밴드 변형, 앉아서 밴드 벌림, 기립 준비, 지지한 한발 서기, 방향 전환 준비를 포함한다. 첨부 기록지는 임상시험 근거가 아닌 작성 사례다. 사례의 질환 원인 설명·효과·불안정한 지지면/외란 자극·일률적인 유지시간을 모든 대상자에게 일반화하지 않는다. 학습을 이유로 진단 기준·권장 용량·안전 게이트를 변경하지 않는다.

## 사용하는 방법

1. 현재 상태·안전·가능 자세·도구·목표를 확인한다.
2. 운동 프로그램의 **이번 회차 중점**을 선택하면 관련 사례 패턴이 후보 순위에 반영된다. 기존 평가와 목표가 우선이며, 무작위로 같은 뜻의 문장만 바꾸지 않는다.
3. 선택한 운동의 **작성 사례 참고**에서 방법과 단서를 읽고 계획 초안에 반영한다. 안전·자세·도구 조건이 미확인이면 버튼이 비활성화된다. 기존 방법이 있으면 바꾸기 전에 확인한다. 실제 시행 횟수·관찰 결과는 자동 채우지 않는다.
4. 실제 수행 기록에서 **단서·보상동작·현장 조정**을 확인한 값으로 입력한다. 이 값은 실제 반응·기타사항과 함께 자동 문장, 서비스 기록지, 경과기록에 들어간다.
5. 실제 운동에 **적합 / 다음 회차 조정 필요 / 다음 추천에서 제외** 피드백을 남긴다. 경과기록을 생성하고 **치료사 검토 완료**를 해야 다음 회차에서 활용한다.

이름만 다른 동일 계획을 자동 반복하지 않도록 현재 중점과 검토 피드백에 따라 후보 순위를 조정한다. 같은 조건에서는 같은 운동이 여전히 적절한 후보일 수 있으며, 다양성을 위해 안전·적합성을 버리거나 진행 단계를 자동 올리지 않는다.

## 다음 회차에서 반영하는 것

- 같은 대상자 ID에 속한 이전 회차의 검토 스냅샷만 읽는다. 다른 대상자/계정의 기록, 현재 회차의 미검토 입력, 미래 회차·미래 날짜의 검토는 사용하지 않는다. 검토일은 한국 날짜를 기준으로 비교한다.
- 실제 서비스 날짜와 회차가 더 최근인 피드백을 우선한다. 과거 회차를 늦게 수정했다고 더 최근 회차의 판단을 덮지 않는다. 같은 회차 안에서는 마지막 검토를 우선한다. 동일 검토가 history/reviewed에 중복 저장된 경우 한 번만 센다.
- 적합은 작은 순위 가점, 조정 필요는 작은 감점, 다음 추천에서 제외는 후보 제외로 반영한다. 한 스냅샷의 같은 운동에 피드백이 섞이면 제외·조정 쪽을 우선한다. 반복 검토 횟수 자체로 가점을 계속 늘리지 않는다.
- 중단/미실시·중단 사유·기록된 통증 증가가 있는 항목을 적합 성공 사례로 재사용하지 않는다. 긍정 판단은 임상 효과의 검증을 의미하지 않는다.
- 적합 피드백의 이전 실제 방법·단서는 같은 대상자의 **계획 참고 방법**으로 제시할 수 있다. 이전 통증·진단·보상동작·반응·횟수를 현재 수행 사실로 복사하지 않는다. 참고 방법도 현재 조건을 다시 확인하고 선택해야 한다.
- 화면에서 **이전 검토 피드백 활용**을 끌 수 있다. 과거 기록은 보존하며 현재 평가·목표·중점과 안전 조건으로 추천한다.

## 저장과 검증

기존 소유자 전용 patient_records JSON과 검토 스냅샷을 사용한다. 별도 SQL, 외부 모델 API 키, 공개 학습 데이터 저장소는 필요하지 않다. 입력/피드백을 수정해도 기존 검토본을 조용히 덮어쓰지 않는다. 새 형식은 noteFormatVersion `2026-10-31.cases.v4`로 관리한다. 이전 초안은 필요 시 재생성·검토하며 이력은 유지한다.

단위 테스트는 대상자 격리, 검토 여부, 날짜/회차 순서, 중복, 제외/조정/적합, 통증 증가, 안전 조건, opt-out, 빈 관찰·숫자 기본값 유지 등을 확인한다. 브라우저 테스트는 사례 적용부터 직접 관찰 입력·저장·검토·다음 회차 후보 변경·설정 유지·모바일·A4 한 장 출력까지 확인한다. 이는 소프트웨어 동작 검증이며 임상 타당성 시험을 대신하지 않는다.
