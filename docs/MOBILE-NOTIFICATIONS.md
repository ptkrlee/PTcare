# 회원 구분 · 이용권 요청 · 아이폰 알림 설정

코드 배포와 실제 알림 가동은 별도입니다. **최신 SQL, 최초 관리자, 서버 발송 환경 변수, 데이터베이스 웹훅, 관리자 기기의 수신 허용**을 설정해야 합니다. 이 저장소나 채팅에 실제 서버 비밀 키를 넣지 않습니다.

## 1. 회원과 평가 이용 방식

- 가입 화면에서 **일반회원 / 치료사회원**을 선택합니다. 어떤 유형이든 가입만으로 치료사 인증이나 관리자 권한이 생기지 않습니다.
- 일반회원과 미인증 치료사회원은 이름·생년월일·평가일 입력 → 평가 → 결과지 캡처·인쇄를 이용합니다. 대상자 정보·응답·그림은 **메모리에만 존재**하며 기기 저장소와 서버에 저장하지 않습니다. 새로고침·창 닫기·로그아웃 시 사라집니다. 저장·회차 관리·차팅은 제공하지 않습니다.
- 인증된 치료사회원은 기존의 대상자 1명·8회차 무료 한도와 저장·차팅을 이용합니다.
- **회원정보 · 요청**에서 치료사 인증, 대상자 이용권 추가, 대상자별 회차 추가를 요청합니다. 요청 내용에는 대상자 건강정보를 적지 않습니다. 회원 구분과 요청 내역은 서버에 저장합니다.
- 관리자는 요청함에서 인증/이용권을 승인하거나 사유를 적어 반려합니다. 인증 승인 시 치료사회원으로 전환하고, 이용권 승인 시 요청 수량만 더합니다. 같은 요청을 두 번 승인해도 중복 부여하지 않습니다. 회원은 새로고침하여 결과를 확인합니다.

## 2. 최신 SQL과 관리자

1. GitHub `main`의 `supabase/schema.sql` → **Raw**에서 전체 내용을 복사합니다.
2. Supabase **SQL Editor → 새 쿼리**에 붙여넣고 **Run**을 누릅니다. 이전 버전을 실행했어도 이번 최신 파일을 다시 실행합니다.
3. 기존 기록·이용권·관리자는 보존됩니다. 기존 회원은 치료사회원으로 유지하고, 새 가입은 가입 화면의 일반/치료사 구분으로 생성됩니다.
4. 아직 관리자 지정 전이면 `supabase/bootstrap-admin.sql`에서 이메일을 본인의 홈페이지 가입 이메일로 바꿔 실행합니다. 이미 관리자로 지정했다면 다시 지정할 필요가 없습니다.
5. 홈페이지 새로고침 → 상단 **관리자**를 누릅니다. 관리자 권한은 SQL로 지정한 계정만 가집니다. 이메일 주소를 코드에 적는 것만으로 관리자가 되지 않습니다.

여기까지만 해도 홈페이지의 **관리자 알림 · 요청함**에서 신규 가입과 요청을 확인·처리할 수 있습니다. 화면을 열어 둔 동안 30초마다 새로 확인하며, 휴대폰 잠금 화면 푸시는 아래 설정이 추가로 필요합니다.

## 3. 서버 발송 키 만들기

1. 관리자 화면의 **아이폰 · 이 기기 알림**에서 **최초 서버 알림 설정 · 키 생성**을 펼칩니다.
2. **최초 설정용 키 생성**을 누릅니다. 공개 키, 비밀 키, 웹훅 비밀 값이 이 브라우저에서 생성됩니다. 생성만으로 운영 설정이 바뀌지는 않습니다.
3. 각 **복사** 버튼으로 아래 Vercel 환경 변수에 등록합니다. 이 화면을 떠나기 전에 등록하세요. 비밀 값은 채팅·GitHub·공유 스크린샷으로 보내지 않습니다.
4. 키를 이미 운영 중이면 기존 값을 유지합니다. 교체할 때는 각 기기에서 알림을 다시 켜야 합니다.

원하면 개인 개발 터미널에서 `npm ci` 후 `npm run push:keys`로 생성할 수도 있습니다. 이 명령은 비밀 값을 해당 터미널에 출력하므로 출력 내용을 공유하지 않습니다.

## 4. Vercel 서버 환경 변수

Vercel → PTcare에 연결된 프로젝트 → **Settings → Environment Variables**에서 다음 값을 **Production**에 등록합니다. `VITE_` 접두사를 붙이지 않습니다.

| 이름 | 등록할 값 |
| --- | --- |
| `SUPABASE_URL` | 현재 Supabase 프로젝트의 `https://….supabase.co` 주소 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase Settings → API Keys의 서버용 secret key 또는 legacy service_role 키. Publishable/anon 키와 다릅니다. 서버에만 등록합니다. |
| `VAPID_PUBLIC_KEY` | 앞에서 생성한 공개 키 |
| `VAPID_PRIVATE_KEY` | 앞에서 생성한 비밀 키 |
| `VAPID_SUBJECT` | `mailto:` 뒤에 관리자 연락용 이메일을 붙인 값 |
| `PUSH_WEBHOOK_SECRET` | 앞에서 생성한 웹훅 비밀 값 |

저장한 뒤 **Deployments → 최신 배포 → Redeploy**하여 Ready를 확인합니다. 개발용 Vite 서버만 실행하면 `/api` 서버 함수는 동작하지 않습니다. 서버 키가 브라우저 빌드에 포함되지 않도록 앱 코드와 서버 코드를 분리했습니다.

## 5. 신규 알림 즉시 발송 연결

Supabase **Database → Webhooks → Create a new hook**에서 설정합니다. 프로젝트 UI에 따라 Integrations 안에 Database Webhooks가 표시될 수 있습니다.

- 이름: `ptcare_admin_push`
- 테이블: **public.admin_notifications**
- 이벤트: **INSERT**만 선택
- 유형: HTTP Request
- Method: **POST**
- URL: **https://refittherapy.vercel.app/api/admin-push**
- Headers:
  - `Content-Type`: `application/json`
  - `Authorization`: `Bearer ` 뒤에 Vercel에 등록한 **PUSH_WEBHOOK_SECRET의 실제 값**을 붙입니다. `Bearer`와 값 사이 공백 한 칸을 유지합니다.
- Timeout 입력이 있으면 10000ms 이상으로 설정합니다.

저장합니다. 새 회원가입과 새 요청은 데이터베이스에 알림을 먼저 남기고, 이 웹훅이 서버에 발송을 요청합니다. 서버는 데이터베이스에서 확인한 알림만 처리하며, 임의의 알림 문구·수신 주소를 입력받아 보내는 기능은 없습니다.

## 6. 재시도 연결

`supabase/install-push-retry.sql`을 새 SQL 쿼리에 복사하고 `REPLACE_WITH_PUSH_WEBHOOK_SECRET`을 위와 같은 비밀 값으로 바꿔 실행합니다. 채운 쿼리를 GitHub에 올리지 않습니다.

이 작업은 Supabase Vault에 발송 주소·비밀 값을 저장하고, pg_cron/pg_net으로 **1분마다** 미발송 알림을 확인합니다. 프로젝트에서 해당 확장 기능이 허용되어야 합니다. 웹훅의 일시 실패나 발송 서버 재시작 때도 큐를 복구합니다. 관리자 화면의 **서버 알림 발송 재시도**로 수동 확인도 가능합니다. 반복 실행은 같은 이름의 예약 작업을 갱신하며 새 예약을 계속 추가하지 않습니다.

웹훅은 새 이벤트의 빠른 발송, 예약 작업은 누락·일시 장애의 복구를 담당합니다. 기기·OS·네트워크·집중 모드 등에 따라 도착이 지연될 수 있으며, 즉시 도착을 보장하지 않습니다. 알림이 늦거나 기기 알림 권한이 없어도 관리자 요청함에는 기록이 남습니다.

## 7. 아이폰 홈 화면과 수신 허용

1. 아이폰이 **iOS 16.4 이상**인지 확인합니다.
2. **Safari**에서 https://refittherapy.vercel.app 을 엽니다.
3. 공유 버튼 → **홈 화면에 추가** → 추가를 누릅니다.
4. 홈 화면의 **PTcare 아이콘**으로 실행합니다. 설치한 앱에서 로그인 상태가 공유되지 않으면 관리자 계정으로 다시 로그인합니다.
5. 상단 **관리자** → **이 기기 알림 켜기** → 아이폰의 **허용**을 누릅니다.
6. 등록 완료 표시를 확인합니다. 홈 화면 아이콘으로 실행하면 관리자 업무 화면으로 이동하며, 알림을 누르면 관리자 화면을 엽니다. 로그인이 만료됐다면 로그인 후 확인합니다.
7. 알림을 거절했다면 아이폰 **설정 → 알림 → PTcare**에서 허용합니다. 집중 모드와 알림 표시 설정도 기기에서 조정합니다.

아이폰의 Safari 탭에서 바로 푸시를 켜는 방식이 아니라 **홈 화면 앱에서 허용하는 방식**입니다. 앱스토어 등록이 필요한 네이티브 앱은 아닙니다. 알림은 **이 기기 알림 끄기** 전까지 유지됩니다. 알림을 꺼도 다른 등록 기기의 수신은 유지됩니다.

## 8. 확인 순서

가상 계정으로 가입 → 관리자 요청함에 가입 도착 → 일반회원의 평가가 기기/서버에 저장되지 않음 확인 → 치료사 인증 요청 → 아이폰 잠금 화면 알림 → 알림을 눌러 관리자에서 승인 → 회원 상태 새로고침 → 저장 기능 이용 → 이용권 요청 → 승인 → 중복 부여 없이 한도 증가를 확인합니다.

푸시에는 **신규 가입/요청이 도착했다는 일반 문구만** 넣습니다. 회원 이메일·대상자 이름·생년월일·평가 결과는 푸시 제공자나 잠금 화면에 넣지 않습니다. 회원 이메일과 요청 사유는 관리자 로그인 후에만 확인합니다. 서비스워커는 페이지·API·임상 데이터를 캐시하지 않습니다.

자동 테스트는 모의 API, 가상 푸시 구독 및 임시 PostgreSQL로 권한·중복 처리·전송 로직을 검증합니다. 실제 Vercel 환경 변수·Supabase 웹훅·예약 작업 설치와 실제 아이폰 수신 성공을 자동 테스트 성공으로 대체하지 않습니다.
