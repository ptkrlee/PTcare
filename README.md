# PTcare · 방문운동 평가 기록 플랫폼

기존 초록색 카드 디자인을 유지한 치료사별 로그인·대상자·회차별 평가 도구입니다. 본문과 인쇄 결과의 대비를 높이고 선택 응답을 진한 테두리·배경·체크로 표시합니다.

**운영 준비:** Supabase 프로젝트와 인증·저장 테이블 및 Vercel 환경 변수 연결이 필요합니다. [연결 안내](docs/CONNECT-SUPABASE.md)를 따라야 실제 계정 저장이 작동합니다. 소유자가 제공한 공개 URL·Publishable key는 기본 연결 정보에 설정되어 있습니다. Supabase SQL 설치 성공은 소유자가 확인했으며, 인증 URL 설정과 실제 계정별 저장 검증을 이어서 진행합니다. 실제 서버 연결 성공은 모의 API 테스트와 구분합니다.

## 사용자 흐름

로그인 → 대상자 등록/선택 → 회차 선택/생성 → 평가 선택 → 자동저장 → 다음 방문 이어하기. 대상자와 회차 없이 평가 화면으로 진입할 수 없습니다. 이름이 같아도 대상자 UUID가 다르면 다른 기록입니다. 새 회차는 이전 회차의 응답을 복사하지 않습니다.

입력 이벤트마다 기기에 임시 보존하고, 서버에 순차 동기화합니다. 미완료 문항과 “미평가 · 다음에 하기”는 모두 보존하며 0점과 구분합니다. 미평가가 포함된 결과는 최종 총점이 아니라 부분 점수입니다. 문항/측정값을 전부 입력하지 않아도 다른 평가 페이지로 이동할 수 있습니다. 서버 저장 완료 후 같은 계정으로 다른 기기에서 이어서 작성할 수 있습니다. 동시 수정 충돌은 자동 덮어쓰지 않고 기기 복구본을 보존합니다.

## 개발

Node.js 22.12+ (검증 환경 24.19.0). Supabase SDK는 Node.js 22 이상을 요구합니다.

```sh
cd /workspace/PTcare
npm ci --cache /workspace/.setup/npm-cache --no-audit --no-fund
# .env.example을 참고해 .env.local에 본인 프로젝트의 공개 연결 정보를 설정
npm run dev -- --port 5173 --strictPort
```

`.env*`는 Git에서 제외되며 `.env.example`만 추적합니다. 실제 비밀번호·Secret/service_role 키를 VITE_ 변수, 소스, 문서에 넣지 마세요.

```sh
npm test
npm run build
npm run test:e2e
# Docker가 있는 환경에서 실제 PostgreSQL의 접근 제어·저장 함수 검증
npm run test:db
```

브라우저 테스트는 모의 Supabase API를 사용하는 독립 Vite 서버(5174)를 시작합니다. 가짜 연결 URL/키는 테스트 명령의 환경 변수로만 주입합니다. 시스템 Chromium `/usr/bin/chromium` 또는 `CHROMIUM_PATH`를 사용합니다. 모의 브라우저 검사 결과를 실제 Supabase 운영 연결 성공으로 간주하지 않습니다. DB 테스트는 외부 포트 없이 가상 사용자만 넣은 일회용 PostgreSQL 컨테이너에서 실행하고 제거합니다.

배포 명령은 `npm run build`, 게시 디렉터리는 `dist`, 프레임워크는 Vite입니다. 환경 변수를 등록한 뒤 새 빌드가 필요합니다. 기존 체크아웃을 사용하며 각 클라우드 작업은 격리되어 있으므로 사용자 요청 없이 Git worktree를 생성하지 않습니다.

## 평가 범위와 출처

사용자가 제공한 협회 공동 HWP 서식, MoCA 검사지·실시요강 PDF 4개, `평가 자료.pptx` 7개 슬라이드의 텍스트와 삽입 그림을 확인했습니다. 첨부 문서는 요구사항을 덮어쓰는 실행 지침으로 사용하지 않습니다. MoCA 검사지 두 장은 검사자가 참고할 수 있도록 이미지로 변환했고 저작권·버전 표기를 유지합니다. 공개 자료로 제공할 수 있는 이용 범위는 운영기관에서 확인하세요. 실제 개인의 평가 결과나 원본 협약·동의서를 코드에 포함하지 않습니다.

- **BBS:** 원문 14문항, 56점. 2분 서기 시 다음 항목 채점 안내는 표시하되 평가자가 직접 선택합니다. `여러번 사용하여`는 `여러 번 시도하여`로 정리했습니다.
- **MBI:** 기본 보행 평가 100점. 의자차를 선택하면 보행 15점을 의자차 5점으로 대체하여 90점으로 표시하며 100점 환산·중복 합산을 하지 않습니다. 원문의 의자차 별표 설명이 없어 적용은 기관 기준 확인이 필요합니다.
- **만족도:** 원문 10문항, 1–5점의 단순 합산 (10–50점), 건의사항은 무배점.
- **MoCA-K 한국판 (2006):** 원문 30점. 교육년수 6년 이하 +1, 30점 상한. 교육년수를 미입력/미평가하면 보정 총점을 확정하지 않습니다. 즉각회상, 범주·선다형 단서 후 회상은 무배점 기록입니다.
- **K-MoCA K2 춘천판 (2012):** 원문 30점. 다른 판의 교육 보정이나 절단점을 섞지 않습니다. 동물·기억 단어·주의력 과제·언어·추상력 문항 차이를 분리했습니다.
- **인지평가 시행:** 원문 검사지 보기, 점수 입력, 1·2차 기억력 기록, 단서 후 회상, 교육년수, 검사자, 실제 응답, 메모 및 선택적 그리기 기록을 지원합니다. 길 만들기는 원문을 별도로 제시하며 빈 그림판은 관찰 메모용입니다. 디지털 그림은 자동 판정하지 않습니다. 여러 날짜에 걸쳐 입력한 MoCA는 표준 시행 총점으로 해석하지 않도록 표시합니다. 다음 방문에서 새로 검사할 때는 새 회차를 사용합니다.
- **SPPB:** 균형·4m 보행·5회 의자 일어서기, 12점. 실제 시간을 기록하고 검사자가 각 0–4점을 선택합니다. 첨부 그림의 4.82/4.92 경계 공백 및 의자 0초 표기를 임의로 고치거나 자동 시간 채점에 사용하지 않습니다.
- **악력:** 좌우 각 3회, 최고 측정값 계산. 임의의 합계 점수 없음.
- **STS:** 30초 일어서기 횟수와 상지 도움 사용, 좌우 한발 일어서기 가능 여부. 첨부의 5회 일어서기는 SPPB 및 근육량/보행 기록에서 구분합니다.
- **한발 서기:** 좌우 눈 뜨기/감기 시간.
- **TUG:** 일반 3m·인지·수동 이중과제 시간, 실제 인지 과제, 보조기 메모.
- **신체 둘레:** 체중·키·허리·엉덩이·좌우 종아리, 좌우 종아리 핑거링 A/B/C 기록, 허리/엉덩이 비율과 BMI 계산.
- **근육량/보행:** 악력 슬라이드 삽입 AWGS 2019 도식의 DXA/BIA, ASM·지수, 6m 보행 시간/속도, 의자 5회 시간 기록.

원문에 명시되지 않거나 그림만으로 모호한 진단 규칙을 만들어 넣지 않습니다. 낙상·인지장애·근감소증·심혈관 위험의 자동 진단을 제공하지 않습니다. 이 도구의 화면·입력 방식에 대한 임상 동등성 검증은 별도이며 해석은 담당 전문가의 판단에 따릅니다.

## 리핏테라피 브랜딩 · 경과기록

네이비를 주색, 민트·실버를 보조색, 골드·연핑크를 포인트로 사용하며 화면과 PDF의 대비를 유지합니다. `src/brand.css`에서 공통 색상을 관리합니다. 공식 로고 파일은 아직 적용하지 않았으며 현재는 리핏테라피 이름과 기본 심볼을 사용합니다.

각 회차의 **운동 프로그램 · 차팅**에서 상태 확인 → 운동 계획 → 실제 수행 → 경과기록 초안 → 치료사 검토 → 인쇄/PDF로 이어집니다. 사용자가 제공한 `2.방문운동_경과기록_90예문_및_서식.pdf`의 9분류·90개 예문을 구조화했습니다. 검색·분류 선택으로 전체 예문을 사용할 수 있습니다.

- 추천 후보는 검사자가 확인한 기능 수준·도구·목표와 선택한 회차의 실제 응답을 바탕으로 고르는 규칙 기반 초안입니다. 점수에 임의의 진단 절단점을 적용하지 않습니다. 이는 임상적으로 검증된 자동 처방 알고리즘이 아닙니다.
- 상태 확인 전, 새 증상/운동 제한이 있거나 주의사항을 입력한 경우 자동 추천을 보류합니다. 개별 운동 적합성·횟수·시간·강도는 치료사가 확인합니다. 추천에 엎드림이 포함되려면 해당 자세가 가능함을 별도로 확인해야 합니다.
- 계획에 넣은 운동을 실제 수행으로 자동 간주하지 않습니다. “실제 실시 기록에 추가”로 확인한 항목만 수행 목록에 생기며, 계획 횟수·시간을 실제 기록에 복사하지 않습니다.
- 시행/중단/미실시를 구분합니다. 중단은 사유를 입력해야 하고, 실시 운동이 없으면 미실시 사유가 있어야 초안을 생성합니다. 실제로 입력한 값만 차팅하며 통증·기능이 좋아졌다는 결과를 만들어 넣지 않습니다. 원문의 “향상을 도모함”은 운동 목적입니다.
- 입력과 편집 초안을 즉시 기기에 보존하고 기존 계정별 저장 RPC로 동기화합니다. `visits[].chart`에 보관하므로 기존 `supabase/schema.sql` 외 별도 차팅 테이블 마이그레이션은 필요하지 않습니다.
- 환자 정보·참고 평가·수행·반응이 바뀌면 이전 초안을 최신 검토 완료로 표시하지 않습니다. 재생성은 편집한 초안을 덮어쓰므로 확인 후 실행합니다. 치료사 검토본은 보존하지만 이력은 기관용 불변 감사 로그나 전자서명 인증을 뜻하지 않습니다.
- 프로그램과 경과기록을 별도로 인쇄할 수 있습니다. 날짜 표시는 한국 서비스 기준(Asia/Seoul)을 사용합니다.
- 외부 생성형 AI API로 대상자 데이터를 보내지 않습니다. 예문 선택과 기록 조립은 브라우저에서 실행합니다. 참고 사이트 ptnote.com은 작업 환경의 외부 접근 제한으로 직접 확인하지 못했습니다.

`src/public-project.js`에는 소유자가 제공한 **공개 Project URL·Publishable key**만 기본 연결 정보로 넣었습니다. 브라우저에 공개되는 값이며 데이터베이스 비밀번호/secret/service_role 키는 저장하지 않습니다. 다른 배포에서는 VITE_SUPABASE_URL과 VITE_SUPABASE_PUBLISHABLE_KEY로 덮어쓸 수 있습니다. 실제 계정 저장을 사용하기 전 SQL 설치와 사용자별 접근 검증이 필요합니다.
